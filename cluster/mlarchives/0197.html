Hi All,

I just modified the github code to not require volume sections to have
DEVICE/PARTITION settings. This means StarCluster will automatically
pick a device to attach it to and then use the first partition by default.

If you're using the first partition on each of your volumes, which is
the case for volumes created by starcluster's createvolume command, I
would recommend completely removing DEVICE/PARTITION from your volume
section after updating to the latest github code. The latest github code
will automagically assign devices in a way that avoids colliding with
other existing devices on an EC2 instance (e.g. the scratch volumes).

You can still use the DEVICE/PARTITION settings of course, however,
PARTITION is now integer type. So, if you want to keep your existing
DEVICE/PARTITION settings for whatever reason, please replace each
PARTITION setting with just the partition number and not the device prefix.


~Justin
