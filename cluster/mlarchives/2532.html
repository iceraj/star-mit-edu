I am considering the following options:
Option 1:
1) Launching an "imagehost" with an AWS AMI that already has CUDA on it (
https://aws.amazon.com/marketplace/pp/B00FYCDDTE)
2) Installing star cluster on it (
/cluster/docs/latest/installation.html)
3) Create an EBS-backed AMI from this:
/cluster/docs/latest/manual/create_new_ami.html

Option 2:
1) Launching an "imagehost" with one of the public starcluster AMIs (eg, [11]
ami-12b6477b us-east-1 starcluster-base-centos-5.4-x86_64-ebs-hvm-gpu-rc2)
2) Updating its cuda version (
http://docs.aws.amazon.com/AWSEC2/latest/UserGuide/using_cluster_computing.html#install-nvidia-driver
)
3) Create an EBS-backed AMI from this:
/cluster/docs/latest/manual/create_new_ami.html

Would both of these methods work? Is one preferable to the other? Is
option #1, step 2, the correct way of installing star cluster on an AMI for
it to work correctly with star cluster?

Avner

> Hi Avner,
>
> This is a quick answer, until one of the specialist returns with a better
> one.
>
> First, you have to make sure that the instance you are renting from Amazon
> will be compatible and have the GPU hardware you need.
>
> Then, the safest thing is to run the AMI on your selected instance and see
> if your software runs outside StarCluster using the Amazon interfaces. If
> you see you have all the software and hardware you need, move to configure
> StarCluster to create a cluster with your AMI.
>
> Each AMI has many software tools on it, so chances are that unless
> specific software is advertised you need to check if it exists by running
> it. Yet note that AMI and instance are separate definitions.
>
> I hope this gives you something to work with.
>
> Jacob
