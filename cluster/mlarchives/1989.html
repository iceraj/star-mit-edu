Hi Justin,

It was a bug in AWS us-east-1 region which was fixed after a couple of
days. The user data attribute of instances launched using one API call was
empty (on except the one with ami launch index = 0). As a result the
instances launched had no 'alias' tag.

It might be worth exploring if the dependence on user data attribute for
tag setting can be removed. Have seen a couple of times in the past when
fetch of user data attribute did not exceed (with few retries) due to may
be API latency issues at AWS end.

Thanks
Mayank
